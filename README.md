# Prompt Studio · Windows 本地作品与提示词工作室

**v0.2.1** · vibe coding by Haifeng.

© 2026 Haifeng. All rights reserved.

Windows 本地 T2I、T2V、I2V 作品与提示词管理工具，通过本机浏览器使用，全部资料留在本机，不接生成接口。提供免安装的 Windows x64 便携包。

## 打开

从 [GitHub Releases](https://github.com/PltuoWang/vibecoding-app/releases) 下载 Windows x64 ZIP，解压后双击 `Start Prompt Studio.cmd`。便携包内置 Node.js，无需安装开发工具。保持启动窗口开启，保存编辑后关闭窗口即可停止服务。

双击启动时，资料默认保存在 `%LOCALAPPDATA%\Prompt Studio\data`，与程序目录分开。升级前建议创建完整备份，再将新版程序解压到新目录。

从源码运行：安装 Node.js 22+（建议 24 LTS），运行 `node launcher.mjs`；也可执行 `npm start` 直接启动服务，默认访问 http://127.0.0.1:4173/ ，这种开发模式将资料保存在项目的 `data/`。可用 `PORT` 和 `DATA_DIR` 覆盖端口与资料目录。运行时无需安装第三方 npm 依赖。

## 推荐体验顺序

1. 新建提示词组，填写名称，加入图片、视频或提示词。新建时提示词保持空白。
2. 图片支持拖入、文件选择、Ctrl+V 或“粘贴图片”；视频支持拖入、文件选择。
3. 导入视频会自动标记为 T2V；在“版本信息”中也可选择 T2I / T2V / I2V。
4. 在作品下直接修改正向、负面提示词，自动保存当前版本。点击“复制提示词”一键复制。
5. 微调时点击“复制为新版本”，复制提示词和参数，结果作品留空；点击“创建新版本”则从空白提示词、空白参数和空白作品开始。
6. 视频可播放、暂停、拖动进度、放大；暂停在喜欢的画面后点击“截取当前帧”，新增 PNG，原视频保留。截帧图片还可继续按比例裁切。
7. 点击顶部“保存”，将当前作品与提示词导出为同名文件；可记住默认文件夹。重复保存自动加相同序号，不覆盖已有文件。
8. 在“设置与备份”创建完整文件夹备份。恢复时填写备份文件夹完整路径，合并为副本，保留现有资料。

## 已实现

- 分组、版本、收藏、回收站、全文搜索、来源/标签筛选、图片/视频筛选，网格与列表视图。
- 同一版本混合管理图片与视频；显示像素尺寸、比例、视频时长和文件大小。
- 支持 PNG、JPG、WebP、GIF、MP4、WebM。新图片每张最多 32 MB，视频每段最多 512 MB，每个版本最多 30 份作品。
- 图片裁切：自由、原图比例、1:1、9:16、16:9、4:3、3:4、3:2、2:3；移动选框和四角缩放，另存结果，保留原图。
- 单个作品删除、组删除的明显入口与确认。组可以从回收站恢复。
- 直接编辑提示词，自动保存；已有旧草稿不阻挡其他版本编辑和新建。
- 两个版本并排比较提示词变化与各自第一份作品，视频可分别播放。
- 记录来源、模型、Seed、修改说明；可选视频参数：帧率、目标时长、镜头运动、主体运动。这些是手动记录的创作参数，与视频自动识别出的实际时长区分。
- 视频/图片与 TXT 同名导出，保留原文件字节；TXT 包含正向提示词、负面提示词和创作参数。没有作品时可仅导出提示词。
- 完整文件夹备份包含版本、草稿、回收站以及独立媒体原文件；支持旧版 JSON 备份合并导入。
- 蓝色强调色、浅色/深色主题；记住外观与默认导出目录。
- 新作品独立存储、重复文件按内容去重、上传进度与取消、分段读取视频，修改提示词无需重写视频。
- 原子保存、多窗口写入冲突检测、旧资料自动升级前备份、恢复时校验文件完整性。

## 资料存储与备份

- 默认 `data/library.json` 保存组、版本、提示词、参数、媒体引用和小封面。`data/media/` 保存新导入的图片与视频副本，原文件移动不影响使用。`data/settings.json` 保存默认导出位置。
- 旧图片继续保留在原来的 JSON 内，不重新压缩；内置演示 SVG 使用应用自带 `public/assets`。
- 首次从旧版升级会在资料目录的 `upgrade-backups/` 中写入原始 JSON，再升级数据结构并提升版本号。旧页面过期写入会被拒绝，刷新后继续。
- 完整备份形如 `Prompt-Studio-备份-日期-编号/backup.json` 和 `media/`；务必一起保管。`backup.json` 单独拷贝不能代替完整备份。内置演示插画随应用提供。
- 恢复会校验独立媒体文件的 SHA-256，缺文件、文件损坏、过期窗口冲突时拒绝改写资料库。
- 删除作品仅移除资料引用，不自动清理独立文件；目前不提供单个作品撤销，请通过删除前的完整备份恢复。组删除有回收站。

## 当前边界

- 文本、封面和旧嵌入图片的 JSON 资料上限约 40 MB。独立媒体原文件不计入这个上限，受磁盘空间限制。正式大规模资料库可沿现有媒体接口迁移到 SQLite。
- 视频能否预览取决于本机浏览器对其编码的支持。无法预览时仍可保存原文件；尚不转码、剪辑或裁切视频。
- GIF 裁切为静态图片。裁切输出最多 4000 万像素、32 MB。像素取整后近似比例会标记“≈”。
- 多窗口冲突时不会覆盖已有文件。请先复制当前尚未保存的提示词到其他位置，再刷新。完整备份反映已经保存的服务端资料。
- 暂不自动解析 ComfyUI 工作流、调用生成接口或管理模型文件；便携包不是 Windows 安装程序。内置插画与提示词均为演示内容。
- 导出/备份目录通过填写本机完整路径设置，例如 `E:\图片收藏`；暂未接原生文件夹选择器。

## 开发与验证

`node --test tests/*.test.mjs`。本次 30 项检查通过，验证细节见 `TEST-RESULTS.md`；模块结构与扩展方式见 `ARCHITECTURE.md`。

VS Code 的“运行和调试”提供本地服务（4174）、版本管理测试、媒体与备份测试、浏览器原型入口。调试和验证使用单独资料目录。

快捷键：Ctrl+K 搜索，Ctrl+V 粘贴图片；普通版本 Ctrl+S 保存当前编辑，旧草稿 Ctrl+S 保存为新版本；裁切选框支持方向键、Shift 加速。

## 发布构建与版权

在 Windows 上运行 `npm run release`，生成 Windows x64 便携包、源码包及 SHA-256 校验文件。构建脚本从 Node.js 官方站点取得运行环境，并按官方校验文件验证；发布清单显式排除资料库、备份、测试输出与本地配置。

`public/version.js` 与 `package.json` 中的版本号保持一致。发布文件写入 `dist/`，不会提交到源码仓库。
